Cette visite va-t-elle se terminer par un achat ?

Pour l'équipe marketing d'un site marchand : repérer pendant la visite les sessions qui vont acheter, pour leur proposer une aide, une offre ou un rappel de panier.

Tâche

Classification binaire supervisée. Cible Revenue : 15,5 % d'achats.

Métrique

F1 sur la classe « achat », avec le rappel et l'AUC. Rater un acheteur coûte le plus cher.

Référence à battre

« Jamais d'achat » : 84,5 % d'exactitude, mais F1 = 0.

Équipe Synora · Khaled Mnejja · Omar Zouari · Omar Idriss · Tawfik Zayen · Rayen Hsairi

Données

12 330 visites d'un site marchand, et trois pièges

  • Source : Online Shoppers Purchasing Intention, UCI (CC BY 4.0), 18 colonnes : pages vues et durées, taux de rebond et de sortie, mois, type de visiteur.
  • Qualité : aucune valeur manquante ; 125 doublons (des rebonds) retirés avant le découpage ; « June » renommé ; pas de janvier ni d'avril.
  • Durées extrêmes : 867 visites de plus d'1 h (onglet oublié), gardées.

Les pièges du sujet

  • Classes déséquilibrées : 15,5 % d'achats, l'exactitude est trompeuse.
  • PageValues : 56 % d'achats quand elle est > 0, contre 4 % sinon. Calculée à partir des achats : connue trop tard ?
  • Codes : Region, Browser, TrafficType… sont des catégories : la région 8 n'est pas « plus » que la région 2.

On compare tous les modèles avec et sans PageValues.

Ce qu'on a retenu

  • Tous les modèles battent la référence (F1 = 0).
  • Au seuil 0,5, la forêt semblait la pire (0,138) : comparer chaque modèle à son meilleur seuil.
  • Gradient boosting sans PageValues, réglé par GridSearchCV : learning_rate = 0.05, max_depth = 6.
  • Tous les modèles réglés : la forêt fait jeu égal (écart 0,005, dans le bruit). Le choix tient.

Où il se trompe

  • Visiteurs réguliers : rappel 54 %, contre 77 % pour les nouveaux.
  • Sur un mois jamais vu : F1 0,334. Le test est optimiste pour une nouvelle période.
  • Par région : pas d'écart net (0,55 à 0,64 pour les régions d'au moins 30 acheteurs).

Usages à éviter

  • Décider seul, à la place de l'équipe marketing.
  • Fixer des prix selon la région ou le type de visiteur.
  • Un autre site ou une autre période sans réentraîner.
  • La version avec PageValues en direct.

Déploiement · démonstration

Une application Streamlit, surveillée et réentraînable

Dans l'application

  • On saisit une visite, on obtient la probabilité d'achat et le seuil d'alerte.
  • Elle refuse les saisies impossibles : aucune page vue, durée sans page.
  • Elle rappelle les limites, avec les chiffres du test lus dans le modèle.

Fiabilité

  • Mêmes versions dans Colab et en production (scikit-learn 1.6.1).
  • 6 tests automatiques de l'application, tous réussis.
  • Aucun chiffre écrit à la main.

Après la mise en ligne

  • Suivi par lot : dérive des entrées (PSI), part d'achats annoncés, rappel.
  • Réentraîner si une alerte se répète, et ne remplacer le modèle que s'il bat l'ancien.

Démonstration en direct : une visite normale, puis une saisie absurde.
